Your task

You are reviewing retrieval gold candidates for OfflineRAG. For each case (a question / query), you will see a pool of candidate passages. Your job is to judge how relevant each candidate is to the effective query shown for that case.

Human judgments are authoritative. Model prelabels shown under each candidate are advisory only — use them as hints, not as the answer.

  1. Obtain the private bundle.json file from the project owner (secure share). Do not upload it to public sites.
  2. Click Load bundle and select that file.
  3. Work through cases: grade every candidate, optionally edit query/metadata, then Accept / Approve edited / Reject.
  4. When finished (or at checkpoints), click Download result JSON and send that file back to the project owner.

This site does not write to the authoritative project database. Progress is stored only in this browser (localStorage). Always download result JSON before clearing progress or switching browsers.

Relevance grades (0 / 1 / 2)

  • 0 — Not relevant: not materially useful for answering the query.
  • 1 — Supporting: useful context, but not sufficient alone as direct answer-bearing evidence.
  • 2 — Direct answer: directly answer-bearing evidence for the query.

Grade against the Effective query box for the case (not against other candidates). If you change the query text, grades for that case are cleared and must be redone — that is intentional.

Interface map

  • Left sidebar: case list with status, review priority, and how many candidates you have graded.
  • Case panel: effective query, original proposal, category/tags, and action buttons.
  • Save query / metadata: applies query/category/tag edits for the current case. Save before Accept / Approve edited if you changed them.
  • Accept: case is ready as gold without changing the proposed query/category/tags. Requires every candidate graded and at least one grade ≥ 1.
  • Approve edited: same completeness rules, but only when you did change query/category/tags.
  • Reject: case will not be used as gold (you may reopen later).
  • Reopen: move an accepted/edited/rejected case back to pending so you can change grades or metadata.
  • Next unreviewed: scrolls to the next candidate in the current case that still lacks a human grade.
  • Nav buttons (header): move across cases; “Next high-priority pending” jumps to pending cases marked high priority.
  • Download result JSON: exports your judgments for handoff. Do this often.
  • Clear local progress: wipes browser-saved progress for this run id. Does not delete your downloaded JSON files.

Common pitfalls

  • Do not Accept until every candidate has a human grade (0, 1, or 2).
  • Accept stays disabled if you edited the query/metadata — use Approve edited instead (or revert the edit).
  • Model Pass 1 / Pass 2 grades are not your grades; click 0/1/2 yourself for each candidate.
  • If the page reloads mid-review, progress usually restores automatically for the same bundle run id; still re-download result JSON after important work.
  • Do not commit or email the bundle.json to public channels — it contains private source text.
