# Slice 18F — Reproducible Model Representation Build & Provisioning

**Scope status:** HUMAN ACCEPTED.\
**Design status:** PENDING / NOT YET ACCEPTED.\
**Implementation status:** NOT AUTHORIZED.

This document records the accepted release-blocking scope. It does not
authorize model conversion, qualification reruns, provisioning implementation,
artifact publication, or changes to accepted retrieval/generation behavior.

## Objective

A clean supported Seneca installation must be able to obtain or reproducibly
generate the qualified `onnx_fp32_v1` embedding representation from declared,
public/published inputs identified by the release. Normal installation must not
depend on an unpublished ONNX directory copied from a developer workstation.

The qualification boundary should attach to a reproducible representation
generation contract rather than treating one workstation-resident ONNX file
instance as scientifically privileged. Exact artifact hashes remain important
for integrity, provenance, and reproducibility verification.

```text
pinned upstream model + revision
        +
frozen representation-generation contract
        +
frozen toolchain / exporter / opset / precision / optimization / arguments
        ↓
onnx_fp32_v1 build output
        ↓
integrity + runtime/equivalence verification
        ↓
qualified CPU representation
```

## Required design and evidence work

The later 18F design must:

1. Reconstruct and record the exact lineage of the currently accepted
   `onnx_fp32_v1` bundle.
2. Identify every output-affecting input to the conversion, including upstream
   model revision, tokenizer/config inputs, exporter/toolchain versions, ONNX
   opset, precision, optimization policy, and conversion arguments.
3. Run multiple clean regenerations from the frozen inputs and determine
   whether the resulting representation is byte-deterministic.
4. If regenerated bytes differ, characterize the difference before defining
   any equivalence rule; do not assume numerical equivalence from model name or
   source revision alone.
5. If byte identity cannot be established but a reproducible representation
   can be justified, define explicit numerical/semantic equivalence tests and
   tolerances with fixed qualification vectors.
6. Provide a normal provisioning path that requires no unpublished local
   artifact. The eventual implementation may either reproducibly build the
   representation locally or download an official prebuilt output of the same
   reproducible contract and verify it.
7. Retain local `--onnx-source`-style import only as an advanced/offline
   override rather than a normal-install prerequisite.
8. Demonstrate that after provisioning the accepted strict-offline runtime
   behavior remains unchanged.

## Release exit condition

Before public release, starting from a clean supported machine with no
developer-owned model directory and no unpublished binary artifacts, Seneca
must be able to provision a valid `cpu_onnx_fp32_v1` environment using only
public/published inputs identified by the release, then select and execute that
CPU representation successfully under the existing runtime contracts.

## Non-goals

18F does not authorize a new embedding model, retrieval redesign, reranker
change, Gold/evaluation truth change, generator change, CUDA redesign, or
scientific promotion of a regenerated representation without the required
evidence. It does not require a specific artifact-hosting service; a binary
registry/cache is a distribution choice subordinate to the reproducible-build
contract.
