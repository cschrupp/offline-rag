**Subject:** the three global-drain indicators in `lifecycle-observations.json`
**Source session:** `7b95b124c4cd0906`
**Driver source:** `prep/stage2-docker-transport` at `e47cd36c0c9ded3b89a86e4f1ffd2c6b02f7995c`

The original sanitized observation file (SHA-256
`f1c283c768b7e98021280b40635667dd562fdee11ef9961143fc81fddbc2bba0`) is
preserved unchanged. Its fields
`drain_grace_exhausted_observed`, `resources_closed_observed`, and
`runtime_stopped_observed` were generated by searching each submission's
nested `server_events` array. The three events are global journal events with
`ordinal: null`; they are not copied into those per-submission arrays. The
resulting `false` values mean “not present in this per-submission projection,”
not “the drain event did not happen.”

These results are established by the successful driver classification
`NATIVE_STAGE2_LIFECYCLE_COMPLETE`, not by reinterpreting the false projection
fields. The native Docker adapter fails the campaign if any of these checks
fails:

- It waits for the global `drain_grace_exhausted` event and requires
  `active_count == 1`, `query_capacity_held == 1`, and `resources_open == true`
  (`docker_adapter.py` in the driver source, lines 904–922).
- It waits for global `runtime_stopped` after the grace event, rejects any
  `resource_close_while_owned` event, requires exactly one worker terminal
  event, slot release, `resources_closed`, and `runtime_stopped`, and verifies
  worker return precedes slot release and that slot release precedes resource
  closure, which precedes runtime stop (lines 950–1004).
- The observer emits the global events with ordinal `null` and prevents closing
  resources while the operation is active (`stage2_app_server.py`, lines
  804–828 and 861–866).
- `native-lifecycle.json` is written only after all eight `driver.run()`
  outcomes validate; its classification and count are
  `NATIVE_STAGE2_LIFECYCLE_COMPLETE` and 8.

The retained raw per-submission driver journal has SHA-256
`cd888446beaba7f656db97036d556b2c43bdeb2efde03e5b9f316a777446ed6b`; like
the sanitized projection, it contains each submission's event list rather
than the session-wide global event records. Inspection confirms that neither
the raw nor sanitized per-submission artifact contains the three global event
records. The false fields therefore cannot be used as evidence that a global
event was absent. The successful
`NATIVE_STAGE2_LIFECYCLE_COMPLETE` record was emitted only after the adapter's
session-wide event checks above passed, and is the retained completion evidence
for those assertions. This reconciliation uses that completion artifact and
the exact validator implementation; it does not reconstruct missing global
event payloads. The original projection and its hashes remain intact; this
note records the correct scope and meaning of those fields. No lifecycle
submission was repeated.
